How pings work (what you are faking)

  • navigator.geolocation.watchPosition feeds onFix() in public/driver-app/js/app.js while the page is visible.
  • A ping goes out only while the driver is Online: POST /presence {online, latitude, longitude}.
  • Throttle: sent only if ≥ 15 s since the last one and moved ≥ 25 m. A fake location must move more than 25 m every 15 s or more, or nothing is sent.
  • A failed ping (offline / 5xx) is stored in IndexedDB (pings store, max 5000) and flushed later in batches of 200 to POST /presence/history. History pings don't move the live position.
  • Hiding the tab stops GPS; showing it again restarts it and syncs.
  • Geolocation needs a secure context: localhost or HTTPS.

API reference: docs/admin-driver-api.md §25 (/presence) and §28 (/presence/history).

Option 1 — Admin side only: app:driver:simulate

No phone or browser. Sends the same /presence calls the app does, with the shared DRIVER_APP_API_KEY + driver_email (refused in production). Source: fvstexpress-admin/src/Command/DriverSimulateCommand.php.

Setup: fvstexpress-admin/.env.local needs DRIVER_APP_API_KEY (any long random string). The driver needs a login (Admin › Staff, Driver role).

Run from the fvstexpress-admin folder:

php bin/console app:driver:simulate -d driver@example.com -i 15
FlagWhat it does

php bin/console app:driver:simulate -s driver@example.com
php bin/console app:driver:simulate -d driver@example.com --offline

Limitation: position drifts randomly (~150 m per ping) inside Metro Vancouver; it does not drive towards the drop-off. Good for the Drivers roster, Live Tracking, Route Map and the stationary exception.

Option 2 — Real driver app in Chrome: DevTools Sensors

Tests the whole client path: throttle, payload, and the GPS fix attached to Delivered / proof photo.

  1. Open the driver app on localhost or HTTPS and log in as the driver.
  2. DevTools (F12) → ⋮ → More tools → Sensors → Location → "Other…" → enter lat / lng.
  3. Toggle Online.
  4. Change the coordinates by more than 25 m, at least 15 s apart, e.g. 49.2827, -123.1207 → 49.2850, -123.1180 → 49.2875, -123.1150.
  5. Each change sends POST /presence. Check DevTools Network and the admin Live Tracking page.

Automatic route (console script)

Paste into the DevTools Console on the driver app, then switch to another tab and back (that restarts GPS with the fake). Replace the points with a path from the pickup to the drop-off. Paste again after any page reload.

(() => {
  const route = [
    [49.2827, -123.1207], [49.2800, -123.1150], [49.2760, -123.1090],
    [49.2700, -123.1000], [49.2650, -123.0950],
  ];
  let i = 0, subs = {}, n = 0;
  const fire = () => {
    const [lat, lng] = route[Math.min(i++, route.length - 1)];
    console.log('[fake-gps]', lat, lng);
    Object.values(subs).forEach(cb => cb({ coords: { latitude: lat, longitude: lng, accuracy: 5 }, timestamp: Date.now() }));
  };
  setInterval(fire, 16000); // > 15 s throttle
  navigator.geolocation.watchPosition = (ok) => { subs[++n] = ok; fire(); return n; };
  navigator.geolocation.clearWatch = (id) => delete subs[id];
})();

Delivery walk-through

Option 3 — No signal and catch-up (/presence/history)

  1. With Option 2 running and the driver Online: DevTools → Network → throttling → Offline.
  2. Let a few route points pass. Pings are stored in DevTools → Application → IndexedDB → pings.
  3. Set Network back to No throttling. The next successful /presence triggers POST /presence/history and the store empties.
  4. Admin: the driven-route history has no gap; the live position comes from the latest /presence only.

Direct call (payload shape from bin/e2e-driver-flow.php):

POST /driver-api/v1/presence/history
{ "pings": [
  { "latitude": 49.2827, "longitude": -123.1207, "recorded_at": "2026-10-14T09:05:15-07:00" },
  { "latitude": 49.2831, "longitude": -123.1189, "recorded_at": "2026-10-14T09:05:30-07:00" }
] }

Max 500 per request (422 above). Duplicates and malformed points are skipped, not rejected.
